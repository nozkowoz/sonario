The new project's credentials

Supabase → your Sonario project → Settings → API. Saved in this browser only, never sent anywhere except Supabase itself.

Check the URL before you click anything. It must be rwkaofshfatqqkupeqoe — the NEW project. If you paste the old shared project's URL, you'll be signing into the wrong database.

Step 7 — sign in with Google

This creates your auth.users row on the new project. The signup trigger will make a profile and a pending membership; the SQL afterwards promotes it to super.

Needs the wildcard form in the new project's Authentication → URL Configuration → Redirect URLs:
http://localhost:8777/**
A bare http://localhost:8777 entry matches only that exact URL, and this page lives at a path — so without the /** Google will bounce back and be refused.

Step 8 — the Leave Test identity

An anonymous identity, used as a dedicated ordinary member for testing RLS, leave and normal-member behaviour. Migration 0004 makes the signup trigger skip anonymous identities, so its profile and membership have to be inserted by hand — this page generates that SQL with the UUID already filled in.

Sign out first if you're currently signed in as yourself, or you'll just see your own session again.

Also: anonymous sign-ins are OFF by default on a new project. Turn them on at Authentication → Sign In / Providers → Anonymous sign-ins before using this button.
